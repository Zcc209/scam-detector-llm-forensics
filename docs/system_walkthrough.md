# 系統運作說明

本文件說明：丟一個網址進去，系統依序做了什麼、每個模型負責什麼、網頁上每個區塊代表什麼。

範例網址：`https://www.instagram.com/某帳號/`（一個 Instagram 帳號首頁）。

## 系統主軸：三層

| 層 | 目的 | 做什麼 |
|---|---|---|
| **第一層　安全取得** | 在不讓使用者或系統暴露風險的前提下，拿到「真正看到的內容」 | 網域檢查（已知涉詐網域＋品牌仿冒網域）、受保護的瀏覽器開啟頁面與連結 |
| **第二層　多模態證據分析** | 從文字、圖片、帳號、連結四個面向各自找證據，每一項都能對回原文 | 網頁文字優先＋OCR 補圖片內文字、MacBERT、帳號特徵、LLM 證據抽取、影像鑑識、連結跳轉追蹤 |
| **第三層　可信決策** | 把證據合成結論，並在不確定時誠實地說「不確定」 | 融合模型 → Conformal 拒答（需要人工查證）→ 硬證據安全升級 |

網頁上的「分析進度」也照這三層分組。

---

## 一、一個網址丟進去之後的完整流程

網頁前端（`ui/app.js`）把網址送到 `web_server.py`。後端開一個子行程執行 `run_pipeline.py`，上限 10 分鐘。每完成一步就寫入 `progress.json`，前端每秒讀一次。

### 第一層　安全取得

| 步驟 | 技術 | 做什麼 | report.json 欄位 |
|---|---|---|---|
| 輸入確認 | — | 拒絕含空白、帳號密碼、內網位址的網址（防 SSRF） | — |
| 網域檢查 | `domain_check.py` | **只負責兩類已知風險**：①列在 165 涉詐網域公告（7.5 萬筆）；②模仿知名平台或品牌的仿冒網域（如 `instagrarn.com`、`line-tw.cc`）。命中就**不開啟網頁**。這一步**不宣稱能抓到所有新出現的詐騙網站**；沒命中的網域會標為「一般網站」，交給第二層的內容與連結分析判斷 | `domain_analysis` |
| 頁面擷取 | Playwright Chromium（無頭模式） | 開啟網頁；每一次跳轉前都重新做網域檢查（CDP Fetch 攔截），擋下載與彈窗。頁面穩定後截圖，並記錄**同一個畫面**裡的網頁文字與位置（可見 DOM）、外部連結。遇到登入牆、404、被彈窗遮住，回報「無法取得內容」，不拿去評分 | `browser_capture` |

### 第二層　多模態證據分析

**文字的處理順序是「網頁文字優先，OCR 只補圖片裡的字」**，不是所有內容都經過 OCR：

1. **網頁文字（DOM）優先**：直接取得網頁上的文字，先濾掉「登入」「註冊」、選單、熱門標題等介面文字（`content_filter.py`；含聯絡方式、連結、金額的行一定保留）。
2. **OCR 只處理圖片內文字**：EasyOCR 讀截圖後，逐一比對每個字框下方有沒有網頁文字（`alignment.py`）：
   - 有而且相同 → **網頁已有**，不重複計分（去重）
   - 有但 OCR 讀錯（如 Instagtm）→ **已更正**，改用網頁上的正確文字（校正）
   - 沒有網頁文字 → **圖片內文字**，只有這部分送去文字模型
3. **例外**：網頁內容一直在變動（例如輪播圖），無法取得穩定的網頁文字時，才改用整張截圖的 OCR 文字當作主要文字。截圖模式沒有網頁可讀，也是用 OCR 文字。

| 證據 | 技術 | 做什麼 | 欄位 |
|---|---|---|---|
| 文字分類 | MacBERT（社群貼文微調版） | 網頁文字、圖片內文字**各自**給一個「像詐騙文案」的分數 | `evidence.dom.model`、`image_analysis` |
| 帳號特徵 | `account_signals.py` | 站外聯絡、短網址、保證獲利、投資招攬、匯款、限時、免費贈送、兼職、冒充機構、粉絲數、驗證標章等，每一項附原文 | `account_signals` |
| LLM 證據抽取 | 本機 Ollama `qwen2.5:7b` | 判斷文字是「招攬讀者」還是「討論／新聞／分享」，列出 13 類詐騙手法並附**逐字引用**（引用不在原文就剔除，防幻覺）。**定位是證據抽取與可解釋性，不是主要的準確率來源**：消融實驗顯示加入 LLM 對 F1 的影響很小（數字見 README 的「實測成效」），它的價值在於讓每個結論都有看得懂、可核對的理由 | `llm_evidence` |
| 影像鑑識 | `image_forensics.py` | ①pHash／dHash 比對 948 張官方確認的詐騙圖片；②ELA 壓縮誤差；③EXIF 編修紀錄；④畫面品牌與網址是否相符 | `image_forensics` |
| 連結跳轉追蹤 | `link_tracer.py`（用第一層的受保護瀏覽器） | 實際點開頁面連結與截圖中的網址，追到落地頁：165 清單、仿冒、冒用品牌、跨 3 個以上不同網站、LINE／Telegram 群組、一頁式購物、投資招攬落地頁。總時間上限 150 秒。**未知的新詐騙網域主要靠這一步和內容分析抓出來** | `link_trace` |
| 分布外偵測 | `ood.py`（Mahalanobis，PCA 64 維） | 文字和訓練資料差太多時，**只提醒「文字分數參考價值較低」，不會改變任何結論** | `ood` |

### 第三層　可信決策

順序固定是「**模型先下基礎結論，硬證據再做安全升級**」：

| 順序 | 技術 | 做什麼 |
|---|---|---|
| ① 融合 | 有符號限制的 logistic 堆疊（27 個特徵） | 把第二層的證據合成融合分數。風險證據只能推向詐騙、無害證據只能推向正常；每項影響力（w·x）都列出來 |
| ② 拒答 | Mondrian split conformal（α = 0.1） | 用校準資料（沒參與訓練的官方判定案例）算出兩條門檻：只剩「詐騙」→ 疑似詐騙；只剩「正常」→ 未發現；兩者都無法排除 → **需要人工查證**。每一類真實案例至少 90% 會被涵蓋（統計保證） |
| ③ 硬證據升級 | `run_pipeline.py` | 在①②的基礎結論之上，遇到硬證據**只會提高風險**：連結追蹤命中高風險、截圖網址在 165 清單、品牌與網址不符、與已知詐騙圖幾乎相同 → 高度疑似；連結有多項中度可疑 → 至少疑似。唯一例外是截圖文字少於 30 字又沒有任何具體證據時，改為需要人工查證（避免硬判） |

模型不是多餘的：硬證據只涵蓋「已知」的風險（名單、仿冒、已知圖片），大多數詐騙貼文沒有這些特徵，要靠模型判斷。網頁上遇到規則升級時，結論卡會同時寫出「模型的基礎結論」與「升級原因」。

**「需要人工查證」是安全設計，不是做不到**：證據不足或互相矛盾時不硬判，避免把正常帳號冤枉成詐騙，也避免把詐騙誤放成正常。實測數字（交給人工的比例、有下結論的案例準確率）見 README 的「實測成效」②，與「每一筆都強制判定」的①分開呈現。

### 融合分數怎麼算

融合模型（`fusion_model.py`）是一個**有符號限制的 logistic regression**，把第二層的證據變成 27 個特徵：

| 特徵群組 | 特徵 | 怎麼轉成數字 |
|---|---|---|
| 文字 | `text_logit`、`text_missing` | MacBERT 的 logit 差值（詐騙 − 正常），截在 ±8 之間再除以 4；沒有文字時 `text_missing` = 1 |
| 圖片內文字 | `ocr_logit`、`ocr_missing` | 同上，只算圖片裡才有的字 |
| 帳號特徵 | 站外聯絡、短網址、保證獲利、投資招攬、匯款／虛擬貨幣、催促、免費贈送、兼職、冒充機構、驗證標章、新帳號、大量粉絲、隨機數字帳號、簡體字（14 項） | 有出現 = 1，沒有 = 0 |
| LLM | 手法數量、是否招攬、是否直接要求讀者、風險等級、是否為討論／新聞／分享、`llm_missing` | 手法數量與風險等級除以 2（上限 2），其餘 0／1 |
| 影像鑑識 | 與已知詐騙圖相符、品牌與網址不符、編修軟體紀錄 | 0／1 |

融合分數 = 1 ÷ (1 + e^(−z))，其中 z = 截距 ＋ Σ（權重 × 特徵值）。

- **權重是從資料學來的**：用訓練切分的官方判定案例＋PTT 一般文章擬合，類別與帳號群組都做了權重平衡，並加 L2 正則化。
- **符號限制**：風險證據的權重只能 ≥ 0（只能推向詐騙），驗證標章、大量粉絲、LLM 判為討論這三項只能 ≤ 0（只能推向正常），「缺少某種證據」的特徵不限制。這樣可以避免學到資料偏誤（例如官方資料裡很多詐騙貼文看起來像閒聊，沒有限制的話「像閒聊」反而會被當成詐騙證據）。
- 很多權重會被壓到 0，代表那項證據在訓練資料裡沒有額外幫助（例如站外聯絡「加 LINE」：在訓練資料的詐騙與非詐騙貼文中都很少出現、比例也差不多，沒有區分力，所以權重是 0）。它仍會顯示在「判斷依據」裡當作說明。
- 目前每一項的權重、截距與兩條門檻都列在[實驗結果的「融合模型權重與門檻」](experiment_results.md#融合模型權重與門檻)，由 `run_experiments.py` 自動產生。

### 四種結論怎麼區分

依下面的順序判斷，前面命中就停：

| 順序 | 條件 | 結論 |
|---|---|---|
| 1 | 網址在 165 清單、是仿冒網域，或跳轉途中遇到這類網域 | **高度疑似詐騙**（不開啟網頁） |
| 2 | 頁面無法取得內容（登入牆、404、已下架、被彈窗遮住） | **需要人工查證** |
| 3 | 融合分數**高於正常門檻**（只剩「詐騙」） | 模型基礎結論：**疑似詐騙** |
| 4 | 融合分數**低於詐騙門檻**（只剩「正常」） | 模型基礎結論：**未發現明顯詐騙跡象** |
| 5 | 融合分數**夾在兩條門檻之間**（詐騙與正常都保留） | 模型基礎結論：**需要人工查證** |
| 6 | 在 3～5 之上檢查硬證據：連結追蹤命中高風險、截圖網址在 165 清單、畫面品牌與網址不符、與已確認詐騙圖幾乎相同 | 提高為**高度疑似詐騙** |
| 7 | 連結跳轉有多項中度可疑特徵，而目前是「未發現」或「需要人工查證」 | 提高為**疑似詐騙** |
| 8 | 截圖模式、目前是「疑似詐騙」，但截圖文字少於 30 字且沒有網址、手法、帳號、圖片等任何具體證據 | 改為**需要人工查證** |

兩條門檻不是人訂的，而是 conformal 用校準資料算出來的：詐騙門檻保證真正的詐騙至少 90% 會保留「詐騙」，正常門檻保證真正的正常至少 90% 會保留「正常」。所以：

- **高度疑似詐騙**只由硬證據（名單、仿冒、冒用品牌、已知詐騙圖、高風險連結）產生。
- **疑似詐騙**是模型單獨判斷的最高等級。
- **未發現明顯詐騙跡象**需要模型有把握是正常，而且沒有任何硬證據。
- **需要人工查證**代表證據不足或互相矛盾，系統不硬判。

### 截圖模式有什麼不同

上傳截圖時沒有網頁可開：OCR → 找出截圖中的網址 → 對每個網址做網域檢查 → 追蹤這些網址 → 其餘相同。OCR 文字直接當作主要文字。

### 可解釋性（選用）

勾選「產生熱點圖」時，`attribution.py` 逐段拿掉文字看分數變化，並用 Integrated Gradients 算每個字的貢獻，畫在截圖上。

## MacBERT 的三個版本

| 版本 | 是什麼 | 訓練資料 | 做法 |
|---|---|---|---|
| **原始 MacBERT**（推測為 `hfl/chinese-macbert-base`；最初版的設定檔沒有記錄來源，但結構一致：12 層、768 維、詞表 21128） | 哈工大訊飛聯合實驗室釋出的中文預訓練語言模型 | 大量一般中文語料 | 預訓練時用「近義詞替換」取代 [MASK] 的遮罩語言模型；本身不會判斷詐騙 |
| **最初版 `anti_fraud_E3_macbert`** | 專題最早版本的詐騙分類器 | 詐騙**對話**資料（推論時會先去掉「騙子：」「受害者：」這類說話者標記，並把簡體轉繁體，可看出訓練資料是對話形式） | 在原始 MacBERT 上加二分類頭（0 = 正常、1 = 詐騙）做完整微調：3 個 epoch、學習率 2e-5、batch 8 × 梯度累積 2、warmup 394 步、fp16、每個 epoch 評估並保留驗證 loss 最低的版本 |
| **`macbert_social`**（網站實際使用） | 在最初版的基礎上，針對社群貼文再微調 | 訓練切分中的官方判定社群貼文（詐騙／非詐騙）＋ PTT 一般看板文章（困難負樣本）；各平台分別取樣 | 以 `anti_fraud_E3_macbert` 為起點，**全部層**繼續微調（`finetune_macbert.py`）：最多 4 個 epoch、學習率 2e-5、AdamW（weight decay 0.01）、前 10% 步數 warmup 後線性遞減、batch 16、最長 256 token、梯度裁切 1.0；loss 依類別與帳號群組加權平衡（同一帳號的多則貼文合計只算 1 份）；每個 epoch 在校準切分上算 loss，只保存最低的那個（early stopping）；GPU 超過 80°C 自動暫停 |

**為什麼要再微調**：最初版學的是「詐騙對話」，但社群上的詐騙貼文常常看起來像一般廣告或閒聊，而正常的品牌廣告也常出現「限時」「加 LINE」。在官方判定的社群貼文測試集上，最初版幾乎抓不到詐騙；微調後大幅改善（實際數字見 README 的「實測成效」）。

**不會洩漏答案**：微調只用訓練切分；校準切分只用來挑 epoch 與算 conformal 門檻；測試切分完全沒碰過。同一個帳號、同一個 LINE ID 或幾乎相同的文字會被分在同一組，一組只會出現在其中一個切分。

## 二、網頁上每個區塊代表什麼

| 區塊 | 顯示什麼 | 怎麼看 |
|---|---|---|
| **新增分析** | 輸入網址或上傳截圖；進階設定可勾選「產生熱點圖」 | 截圖支援 PNG、JPG、WebP，上限 10 MB |
| **分析進度** | 依三層分組的步驟狀態與完成率 | 被攔截的網址會停在「網域檢查：需確認」 |
| **分析結論卡** | 四種結論之一、一句話原因、詐騙可能性量尺（融合分數） | 規則判定時右側顯示「規則命中」，下方另有一行說明「模型的基礎結論 → 升級原因」；文字太短時顯示「證據不足」 |
| └ 這句話怎麼來的？ | conformal 的兩條門檻、這次分數落在哪一段、信心水準的意思、為什麼會交給人工 | 門檻是用校準資料算出來的，不是人工訂的 |
| **判斷依據** | ▲ 推向詐騙、▼ 推向正常，弱／中／強代表影響力 | 規則命中的項目排最上面，再來是融合模型中影響最大的 6 項 |
| **文字模型分數** | MacBERT 對「網頁文字」和「圖片裡的文字」各自的分數 | 單一模型的原始分數，不是最終結論 |
| **連結跳轉追蹤** | 每個連結一張卡片：來源、跳轉路線、四項固定檢查、其他旗標、落地頁縮圖 | 紅＝高風險（單獨就足以判定）、橘＝可疑、灰＝留意 |
| **LLM 證據抽取** | 語言行為標籤、找到的手法與逐字引用、理由 | MacBERT 和 LLM 意見不同時，會附上驗證資料中同類案例實際是詐騙的比例 |
| **影像鑑識** | 已知詐騙圖片比對、品牌與網址是否矛盾、編修紀錄、ELA 圖 | ELA 亮區只是提示，需人工判讀 |
| **網域與帳號** | 網域檢查結果、分布外偵測（只提醒）、帳號特徵標籤 | 「一般網站」代表不在已知名單、也不像仿冒網域，不代表安全 |
| **截圖上讀到的文字** | OCR 每一行標示「網頁已有／已更正／送去判斷」 | 只有「送去判斷」的行會進文字模型 |
| **檢測畫面** | 原始畫面／文字來源／熱點圖 | 熱點圖需勾選「產生熱點圖」 |
| **原始證據** | 網頁文字、截圖文字、網址紀錄；可下載 JSON 報告 | 給需要查核細節的人 |
| **系統實測成效**（收合） | ①全體分類效能；②加上拒答後的效能；③各平台效能 | ①和②分母不同，不能直接比較；數字讀自正在使用的模型檔 |
