# 系統運作說明與版本比較

本文件回答兩個問題：

1. 丟一個網址進去，系統依序做了什麼、每個模型負責什麼、網頁上每個區塊代表什麼。
2. 和上一版（[ProASQ/topic](https://github.com/ProASQ/topic)）相比，新增了哪些技術與功能；同一個網址，兩版的輸出差在哪裡。

範例網址：`https://www.instagram.com/某帳號/`（一個 Instagram 帳號首頁）。

---

## 一、一個網址丟進去之後的完整流程

網頁前端（`ui/app.js`）把網址送到 `web_server.py`。後端開一個子行程執行 `run_pipeline.py`，上限 10 分鐘。過程中每完成一步就寫入 `progress.json`，前端每秒讀一次，更新「分析進度」的五個步驟。

| # | 步驟 | 用到的技術／模型 | 做什麼 | 產出（report.json 欄位） |
|---|---|---|---|---|
| 0 | 輸入確認 | — | 檢查網址格式，拒絕含空白、帳號密碼、內網位址（防 SSRF） | — |
| 1 | 網域檢查 | `domain_check.py`：165 涉詐網域清單（7.5 萬筆）、仿冒平台規則 | ①網域列在 165 公告中 → **直接攔截，不開啟網頁**；②網域像 `instagrarn.com`、`line-tw.cc` 這類仿冒官方平台的網址 → 攔截；③官方網域（instagram.com、lin.ee 等）標記為「官方網域」，但這不代表帳號可信 | `domain_analysis` |
| 2 | 頁面擷取 | Playwright Chromium（無頭模式） | 開啟網頁。瀏覽器每次跳轉前都先重做步驟 1 的檢查（用 CDP Fetch 攔截），並擋下載與彈窗。頁面穩定後截圖，同時記錄**同一個畫面**裡每段文字的內容與位置（可見 DOM）和頁面上的外部連結。遇到登入牆、404、被彈窗遮住的頁面，回報「無法取得內容」，不拿去評分 | `browser_capture`（截圖、可見文字、外連連結） |
| 3a | 介面文字過濾 | `content_filter.py` | 濾掉「登入」「註冊」、選單、熱門標題這類平台介面文字（這些字會干擾文字模型）。含聯絡方式、連結、金額的行一定保留 | `content_filter` |
| 3b | OCR | EasyOCR（繁中＋英文），OpenCV 深色模式反轉 | 把截圖上的字逐行讀出來，信心太低的行標記為「略過」 | `evidence.screenshot_ocr.items` |
| 3c | OCR↔網頁文字對齊 | `alignment.py` | 比對每個 OCR 字框下方有沒有網頁文字：<br>・有，而且內容相同 → **網頁已有**（改用網頁文字，不重複計分）<br>・有，但 OCR 讀錯（如 Instagtm）→ **已更正**<br>・沒有網頁文字，代表字在圖片裡 → **圖片內文字**，只有這部分送去文字模型 | `region_alignment` |
| 3d | 文字分類 | MacBERT（社群貼文微調版 `models/macbert_social`） | 網頁文字、圖片內文字**各自**給一個「像詐騙文案」的分數。長文用 512 token 滑動視窗 | `evidence.dom.model`、`image_analysis` |
| 4a | 帳號特徵 | `account_signals.py`（規則） | 找出站外聯絡（加 LINE、t.me）、短網址、保證獲利、投資招攬、匯款／虛擬貨幣、限時催促、免費贈送、兼職、冒充機構、粉絲數、驗證標章、隨機數字帳號、簡體字比例；每一項都附原文 | `account_signals` |
| 4b | LLM 證據抽取 | 本機 Ollama `qwen2.5:7b`（JSON Schema 結構化輸出，temperature 0） | 判斷這段文字是「招攬讀者」還是「討論／分享／新聞／介面文字」，列出 13 類詐騙手法，每一項都要附原文引用。**引用在原文找不到就剔除**（防幻覺）。LLM 只負責提供證據，最後的判斷不交給它 | `llm_evidence` |
| 4c | 影像鑑識 | `image_forensics.py`（PIL、numpy、scipy） | ①pHash／dHash 比對 948 張主管機關已確認的詐騙圖片（整張和畫面中的每張圖都比）；②ELA 壓縮誤差分析；③EXIF 編修軟體紀錄；④畫面上出現某品牌（如「7-11 賣貨便」），網址卻不是該品牌的官方網域 | `image_forensics` |
| 4d | 分布外偵測 | `ood.py`：MacBERT [CLS] 向量 → PCA 64 維 → Mahalanobis 距離 | 文字和訓練資料差太多時提醒「文字分數參考價值較低」，本身不改變結論 | `ood` |
| 4e | 連結跳轉追蹤 | `link_tracer.py`（每個連結都用步驟 2 的受保護瀏覽器開啟） | 從頁面連結和截圖文字中挑出最多 4 個外部網址（短網址、通訊軟體優先），實際點開追到最終落地頁，記錄跳轉路線並打旗標：165 清單、仿冒、冒用品牌、跨 3 個以上不同網站（同一平台的網域算同一個）、LINE／Telegram 群組、一頁式購物、投資招攬落地頁、隨機網域、高風險頂級域名。總時間上限 150 秒 | `link_trace` |
| 4f | 學習式證據融合 | `fusion_model.py`：有符號限制的 logistic 堆疊模型（27 個特徵） | 把 3d～4c 的結果合成一個「融合分數」。權重從官方判定案例學來；風險證據只能推向詐騙，無害證據（驗證標章、大量粉絲、LLM 判為討論）只能推向正常。每項證據的影響力（w·x）都會列出來 | `content_analysis.fraud_score`、`contributions` |
| 4g | Conformal 拒答 | `conformal.py`：Mondrian split conformal（α=0.1） | 用 181 筆沒參與訓練的校準案例算出兩條門檻。分數高於「排除正常」門檻 → 只剩詐騙；低於「排除詐騙」門檻 → 只剩正常；夾在中間 → **需要人工查證**。統計上保證每一類的真實案例至少 90% 會被涵蓋 | `content_analysis.prediction_set` |
| 5 | 規則升級 | `run_pipeline.py` | 融合結論之後，依序檢查硬證據：連結追蹤命中高風險 → 高度疑似；連結有兩項中度可疑 → 至少疑似；截圖中的網址在 165 清單上 → 高度疑似；品牌與網址不符 → 高度疑似；截圖文字少於 30 字且沒有任何具體證據 → 需要人工查證；和已確認詐騙圖片幾乎相同 → 高度疑似 | `assessment.risk_level`、`assessment.basis` |
| 6 | 可解釋性（選用） | `attribution.py`：逐段刪除 ＋ Integrated Gradients | 勾選「產生熱點圖」才執行：逐段拿掉文字看分數變化，並對每個字算梯度貢獻，畫在截圖上 | `attribution` |

最後得到四種結論之一：

| 結論 | 什麼情況會出現 |
|---|---|
| 高度疑似詐騙 | 網域在 165 清單上或為仿冒網址（被攔截）、連結追蹤命中高風險、品牌與網址不符、圖片和已確認詐騙圖片相同，或融合分數在 conformal 下只剩「詐騙」且風險高 |
| 疑似詐騙 | 融合分數偏向詐騙，或連結跳轉有多項中度可疑特徵 |
| 未發現明顯詐騙跡象 | conformal 預測集合只剩「正常」 |
| 需要人工查證 | 詐騙與正常都無法排除、截圖文字太短又沒有具體證據，或頁面無法取得內容（登入牆、已下架） |

### 截圖模式有什麼不同

上傳截圖時沒有網頁可開，所以順序改成：OCR → 從截圖文字中找出網址 → 對每個網址做步驟 1 的網域檢查 → 追蹤這些網址（步驟 4e）→ 其餘相同。OCR 文字直接當作帳號文字送進 MacBERT。

## 二、網頁上每個區塊代表什麼

| 區塊 | 顯示什麼 | 怎麼看 |
|---|---|---|
| **新增分析** | 輸入網址或上傳截圖；進階設定可勾選「產生熱點圖」 | 截圖支援 PNG、JPG、WebP，上限 10 MB |
| **分析進度** | 五個步驟目前的狀態（等待中／處理中／已完成／不適用／需確認）和完成率 | 被攔截的網址會停在「網域檢查：需確認」 |
| **分析結論卡** | 四種結論之一、一句話原因、右側「詐騙可能性」量尺（融合分數） | 如果是規則直接判定（165、仿冒、冒用品牌、已知詐騙圖），右側顯示「規則命中」，不看分數；文字太短時顯示「證據不足」 |
| └ 這句話怎麼來的？ | conformal 的兩條門檻、這次分數落在哪一段、90% 信心水準的意思 | 門檻是用校準資料算出來的，不是人工訂的 |
| **判斷依據** | 影響結論的證據清單：▲ 推向詐騙、▼ 推向正常，弱／中／強代表影響力 | 規則命中的項目排最上面，再來是融合模型中影響最大的 6 項 |
| **文字模型分數** | MacBERT 對「網頁文字」和「圖片裡的文字」各自的正常／詐騙比例 | 這是單一模型的原始分數，不是最終結論；圖片文字都已包含在網頁中時顯示「不重複計分」 |
| **連結跳轉追蹤** | 每個被點開的連結一張卡片：來源、跳轉路線（A → B → C）、四項固定檢查（165 清單、仿冒／冒用品牌、跳轉路線、落地頁）、其他旗標、落地頁縮圖 | 卡片顏色看最嚴重的旗標：紅＝高風險（單獨就足以判定）、橘＝可疑、灰＝留意 |
| **LLM 證據抽取** | 語言行為標籤（如「招攬讀者採取行動」）、是否直接要求讀者行動、找到的手法與逐字引用、LLM 的理由 | MacBERT 和 LLM 意見不同時，會出現說明框，並附上驗證資料中同類案例實際是詐騙的比例 |
| **影像鑑識** | 已知詐騙圖片比對結果（有相符會附官方案例連結）、品牌與網址是否矛盾、編修軟體紀錄、ELA 圖 | ELA 亮區只是提示，文字邊緣本來就會偏亮，要人工判讀 |
| **網域與帳號** | 網域檢查結果（官方／一般／165／仿冒）、分布外偵測結果、帳號特徵標籤（紅＝可疑、綠＝加分） | 截圖模式會列出截圖中每個網址的檢查結果 |
| **截圖上讀到的文字** | OCR 讀到的每一行，標示「網頁已有／已更正／送去判斷」，並標出含網址的行；太模糊的行收在「顯示略過的文字」裡 | 只有「送去判斷」的行會進文字模型 |
| **檢測畫面** | 截圖，可切換「原始畫面／文字來源（灰＝網頁已有、橘＝已更正、藍＝圖片內文字）／熱點圖（紅＝推向詐騙、藍＝推向正常）」 | 熱點圖需勾選「產生熱點圖」 |
| **原始證據** | 網頁文字、截圖文字、網址檢查紀錄的原文；可下載完整 JSON 報告 | 給需要查核細節的人 |
| **系統實測成效、熱點圖與分數計算**（收合） | ①融合模型在官方判定測試集上的 Precision、Recall、F1、FPR、AUC，以及拒答比例與困難負樣本誤報率（數字直接讀自正在使用的模型檔，重新訓練後自動更新）；②逐字／逐段的熱點文字；③每個模型的 logits、差值、分數的計算表 | 展開後才看得到 |

## 三、和上一版（ProASQ/topic）的比較

### 上一版的做法

上一版共 6 個 Python 檔，約 1,200 行，介面是 Streamlit：

1. `domain_check`：比對 18 個社群平台的官方網域，用字串相似度找仿冒網址，另外看 HTTP、Punycode、網址帶帳密、非標準 port，加總成 0–100 分。**沒有 165 涉詐清單。**
2. `web_capture`：Playwright 開啟網頁，截一張圖，抓整頁 `body` 文字（含選單、登入按鈕）。放行規則寬鬆：網域含 `cdn`、`static`、`instagram` 等字的請求一律直接通過。
3. **只要抓得到網頁文字，就只把整頁文字送進 MacBERT，完全跳過 OCR**；只有抓不到文字（或圖片模式）才做 OCR。
4. 「硬規則防護網」：文字同時出現金額詞（含「元」）和目標或急迫詞（「目標」「限時」「私訊」）時，**直接把結果改成 Fraud 99%**。
5. 輸出：Fraud／Normal 二選一加信心度、matplotlib 長條圖（含推論延遲），以及原始 JSON。

### 新增的技術與功能

| 類別 | 新增項目 | 做什麼 | 上一版 |
|---|---|---|---|
| 網域 | 165 涉詐網域清單（7.5 萬筆） | 命中就不開啟網頁，直接判定高風險 | 沒有 |
| 網域 | 仿冒規則改良 | 片段比對加上常見單字例外（online、airline、threadless 不會被當成仿冒） | 只比整段網域字串，誤判較多 |
| 擷取 | 每一步跳轉都檢查 | 用 CDP 攔截每次跳轉，先查 165 與仿冒規則，再決定要不要載入 | 網域含 cdn、static 等字就直接放行 |
| 擷取 | 無法取得內容的頁面分類 | 登入牆、404、已下架、被彈窗遮住都明確回報，不拿去評分 | 沒有分類，抓到什麼就拿什麼評分 |
| 擷取 | 同一畫面的可見 DOM | 記錄截圖當下每段文字的位置，讓網頁文字和截圖對得起來 | 抓整頁文字，和截圖內容不一致 |
| 文字 | 介面文字過濾 | 濾掉選單、按鈕、熱門標題，避免干擾模型 | 沒有，「登入」「註冊」也一起評分 |
| 文字 | OCR↔DOM 對齊 | 網頁文字和圖片內文字**都評分**；OCR 讀錯的字用網頁上的正確文字更正 | 有網頁文字就跳過 OCR，圖片裡的詐騙文字完全看不到 |
| 文字 | MacBERT 社群貼文微調 | 用官方判定案例和 PTT 困難負樣本重新訓練（以組別切分，避免資料外洩） | 原始模型對社群貼文 Recall 1.4%、AUC 0.47，幾乎無效 |
| 文字 | 分布外偵測 | 文字不像訓練資料時提醒分數參考價值低 | 沒有 |
| 證據 | 帳號特徵 | 10 類文字規則（站外聯絡、保證獲利、匯款等），加上粉絲數、新帳號、隨機數字帳號、簡體字比例，每一項都附原文 | 只有關鍵字直接改結果 |
| 證據 | LLM 證據抽取（Qwen2.5-7B，本機） | 判斷是招攬還是討論，列出手法並附逐字引用，引用不在原文就剔除 | 沒有 |
| 證據 | 影像鑑識 | 948 張已確認詐騙圖片的感知雜湊比對、ELA、EXIF、品牌與網址不符 | 沒有 |
| 證據 | 連結跳轉追蹤 | 實際點開頁面連結和截圖中的網址，追到落地頁並打風險旗標 | 沒有，只看輸入的那一頁 |
| 判斷 | 學習式證據融合 | 有符號限制的 logistic 模型，權重從資料學習，每項證據的影響力都可以追溯 | 單一模型分數；關鍵字命中就強制 99% |
| 判斷 | Conformal 拒答 | 「需要人工查證」有統計保證，不是人訂的分數區間 | 只有 Fraud／Normal |
| 判斷 | 四種結論＋規則升級 | 高度疑似／疑似／未發現／需人工查證，每一種都附原因 | 二選一 |
| 解釋 | 判斷依據清單 | ▲▼ 方向加上弱／中／強 | 只有信心度長條圖 |
| 解釋 | 熱點圖 | 逐段刪除與 Integrated Gradients，標在截圖上 | 沒有 |
| 解釋 | 文字來源標示 | 每一行 OCR 文字標出網頁已有、已更正、送去判斷或略過 | 沒有 |
| 資料 | 真實資料集 | 數發部通報網官方判定案例（418 詐騙、739 非詐騙）＋PTT 困難負樣本＋行為測試句 | 沒有評估資料 |
| 評估 | 組別不重疊的測試 | Precision 81.5%、Recall 76.8%、F1 79.1%、FPR 11.0%、AUC 0.92 | 沒有量化評估 |
| 介面 | 獨立網頁（HTML/CSS/JS） | 即時進度、各證據面板、系統實測成效、下載報告 | Streamlit，只有轉圈圈 |
| 工程 | 測試與自我檢查 | 92 個單元測試、10 個端對端情境（`scenario_check.py`） | 2 個測試檔 |

### 同一個網址，兩版輸出的差別

以「一個 Instagram 帳號，bio 放了 LINE 連結，貼文圖片上寫著投資群組招攬文字」為例：

| | 上一版 | 這一版 |
|---|---|---|
| 網域 | instagram.com 是官方網域，分數 0 | 同樣是官方網域，但另外標註「網域正確不代表帳號可信」 |
| 看到的文字 | 整頁 body 文字，包含「登入」「註冊」「追蹤」等介面文字 | 濾掉介面文字後的貼文文字，**加上**圖片裡的招攬文字 |
| 圖片裡的字 | 因為有網頁文字，OCR 被跳過，完全沒看到 | OCR 讀出後和網頁文字對齊，只有圖片裡才有的字送去判斷 |
