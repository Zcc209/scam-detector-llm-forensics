# 模型分數、刪除實驗與正式驗證

## 分數來源

MacBERT 不是直接看圖片判斷帳號。EasyOCR 將截圖轉成文字；DOM 是另一份網頁文字。兩者分開經過清理、tokenizer 與 BertForSequenceClassification。模型 config.json 明確設定 index 0 = Normal、index 1 = Fraud，現在程式會檢查此映射，避免權重類別順序被用錯。

每份文字以 512-token 視窗、64-token 重疊推論。先平均各視窗輸出的兩個 logits，再 softmax。二分類等價式為：

`p(Fraud) = 1 / (1 + exp(-(z_Fraud - z_Normal)))`

- 60%：logit 差約 0.405465。
- 10%：logit 差約 -2.197225。
- 50%：兩個 logits 相等。大於 50% 時 Fraud 是較大分數，小於時 Normal 較大。這是二分類 argmax 的數學結果，不是從資料選出的風險門檻。

logits 來自訓練得到的網路權重與本次輸入，不是規則指定的數字。`score_provenance` 記錄當次 logits、差值、切段資訊與計算式，可重算百分比。這解釋計算過程，不保證現實機率可靠，也不能單靠數字知道模型內部的語意理由。訓練樣本、標籤定義、訓練歷程尚需原模型提供者補充。

注意：網域 risk_score 的 60/80 是另一套人工規則分數，**不是 MacBERT 的 60%/80%**；OCR 辨識信心度也不是詐騙分數。網域規則仍是啟發式安全攔截，不能當成已校準的機率。若教授問它的最佳性，目前沒有正式測試集可以支持。

## 已執行的 Dcard 局部敏感度實驗

固定本機權重，用既有 `artifacts/web_temp_output/report.json` 的原始文字逐段刪除。已完成全部 96 段 DOM、23 段 OCR。保留其餘文字順序不變，每次重新執行完整推論。`artifacts/research/dcard-attribution.json` 保存完整紀錄與權重 SHA-256，不上傳第三方服務。

本次 OCR 原始 Fraud 分數約 52.3442%，logits [Normal, Fraud] 約 [-0.259723, -0.165885]，差值 0.093838；softmax 可重現此分數。

|移除文字|移除後 Fraud 分數|降低百分點|
|---|---:|---:|
|學測模擬測驗|35.1421%|17.2022|
|截圖中的 dcard 活動網址|36.2514%|16.0929|
|馬上點擊連結測驗看結果|41.2160%|11.1282|
|註冊|41.4292%|10.9150|
|登入|43.4184%|8.9259|

這些是同一輸入、同一模型的刪除效果。正常平台介面／活動文字也影響分數，顯示此頁的分類對上下文敏感，不能把 Fraud 標籤當成帳號事實。每一筆效果不相加，刪除會改變語境及可能的 token 分段；這不是因果實驗，也不是 Integrated Gradients 或 SHAP。不能宣稱已找到「真正詐騙原因」。

## 正式驗證尚未完成的原因

目前沒有附來源、獨立複核的正常／詐騙社群案例，也沒有可核對的原模型訓練集。把 Dcard 直接當正常標籤、把 165 網域資料當社群帳號標籤，或把合成案例當真實測試，都無法完成可信的準確率與校準驗證。

已有 `evaluate.py` 評估框架，可檢查帳號／網站 group split、比較網址規則、MacBERT 與融合的 Precision、Recall、F1、Unknown coverage 及混淆矩陣。候選 temperature 只在 calibration split 擬合，test split 用於獨立比較 Brier/ECE，不自動部署。這些樣本數檢查只防止過少案例，不代表達到數量就能證明可靠。

需要的資料：每個案例的來源、合法使用截圖／文字、Fraud 或 Normal 標籤依據、複核人、穩定帳號／網站識別碼，及未參與模型訓練的證明。使用 `data/annotation_template.csv` 記錄。同帳號相似內容不跨訓練／校準／測試組。

正式輸出前應依部署需求事先決定誤報／漏報成本，再在校準集選政策，最後只用未碰過的測試集評估並呈現失敗案例。現在不設定另一組主觀門檻來代替這項工作，也不宣稱已驗證完成。
