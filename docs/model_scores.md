# 網站上的各種分數是什麼

網站和 `report.json` 裡會出現好幾種數字，它們的意義和尺度都不一樣，不能互相比較。

| 數字 | 範圍 | 怎麼來的 | 代表什麼 | 不代表什麼 |
|---|---|---|---|---|
| **MacBERT 文字分數** | 0～100% | 文字分類模型的 softmax | 這段文字「像詐騙文案」的程度 | 不是帳號是詐騙的機率，也不是最終結論 |
| **融合分數**（詐騙可能性） | 0～100% | 融合模型把所有證據加權後的輸出 | 綜合文字、帳號、LLM、影像證據後的詐騙傾向 | 分數落在兩條門檻之間時不下結論 |
| **Conformal 門檻** | 兩個百分比 | 用校準資料算出 | 融合分數要多高／多低才下結論 | 不是人工訂的數字 |
| **網域風險分數** | 0～100 分 | 人工規則加總（165 清單 +80、仿冒 +65、HTTP +15…） | 60 分以上就不開啟網頁 | **不是機率**，和上面的百分比無關 |
| **OCR 辨識信心** | 0～100% | EasyOCR 對每一行字的把握 | 低於門檻的行會被略過 | 和詐騙無關 |
| **連結風險等級** | 高／可疑／留意 | 連結追蹤的旗標組合 | 高風險單獨就足以判定 | 不是分數 |
| **判斷依據的強度** | 弱／中／強 | 融合模型中「權重 × 特徵值」的大小 | 這項證據把結果推了多少 | 不是這項證據本身的可信度 |

## MacBERT 文字分數怎麼算

MacBERT 不看圖片，只看文字。網頁文字和圖片內文字（OCR）分開計算。

1. **清理文字**：去掉「騙子：」「受害者：」這類說話者標記，簡體轉繁體。
2. **切成視窗**：每 512 個 token 一個視窗，相鄰視窗重疊 64 個 token，長文也能完整讀到。
3. **每個視窗各得到兩個 logit**（正常、詐騙），把所有視窗的 logit **取平均**。
4. **換算成機率**：`p(詐騙) = 1 ÷ (1 + e^(−(z_詐騙 − z_正常)))`。

幾個對照點：兩個 logit 相等時是 50%；差值約 0.41 是 60%；差值約 −2.2 是 10%。

- 模型的 `config.json` 規定 index 0 = 正常、index 1 = 詐騙，程式啟動時會檢查，順序不對就拒絕執行。
- 每次分析的 `score_provenance` 會記下 logit、差值、視窗數和模型檔的 SHA-256，可以重算出同一個百分比。
- 這個分數沒有另外做機率校準；它是融合模型的一個輸入（先轉成 logit 差值，截在 ±8 再除以 4）。

三個 MacBERT 版本的差別見[系統運作說明](system_walkthrough.md#macbert-的三個版本)。

## 為什麼要濾掉介面文字：一次早期實驗

系統早期（還在用最初版 `anti_fraud_E3_macbert`、還沒有介面文字過濾）對 Dcard 官方 Instagram 頁面做過逐段刪除實驗：每次拿掉一段文字，看詐騙分數變多少。當時整頁 OCR 文字的詐騙分數約 52.3%。

| 拿掉的文字 | 拿掉後的詐騙分數 | 降低（百分點） |
|---|---:|---:|
| 學測模擬測驗 | 35.1% | 17.2 |
| 截圖中的 dcard 活動網址 | 36.3% | 16.1 |
| 馬上點擊連結測驗看結果 | 41.2% | 11.1 |
| 註冊 | 41.4% | 10.9 |
| 登入 | 43.4% | 8.9 |

「登入」「註冊」這種平台介面文字也會明顯影響分數，這就是後來加入介面文字過濾（`content_filter.py`）和社群貼文微調的原因。

這份實驗用的是舊模型，數字只用來說明動機，**不代表現在系統的表現**；原始紀錄只留在本機。各段的效果不能相加，刪除實驗也不是因果證明。
