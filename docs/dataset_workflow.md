# 建立真實案例集：小組操作手冊

## 先決定要測什麼

以「某時間點取得的內容」為案例，不判定帳號永遠安全。Fraud：來源明確指出當次內容涉詐。Normal：可核對的正常內容。Unresolved：資料不足或標註有分歧，不塞進二分類真值。

分開建三組：社群頁面／截圖、文字話術、已知涉詐網域。三者不能互換標籤。警方自製宣導海報不是社群截圖；已停用網站無法重現時只能測網域規則。

## 蒐集步驟

1. 詐騙候選：從警政署／165 公開案例、官方涉詐網站清單，或有同意使用的真實案例找來源。優先找附原始畫面、可核對帳號／網址的案例。只有文字敘述就留在文字組，不把文章內的防詐提醒當成詐騙話術。
2. 正常候選：從品牌／機構官網交叉連到社群帳號，或同意提供畫面的正常使用者蒐集。保留活動、促銷、測驗等容易被誤判的內容。官方網域／認證標記只作身分線索，還要核對當次內容。
3. 每筆建資料夾，保存來源、來源日期、擷取日期、原圖、DOM／OCR、report.json、可用性與使用授權。不能只存模型標籤。
4. 不向可疑站提交個資、不登入、不匯款或下載檔案；被封鎖網站不要繞過。無原始涉詐畫面就保留缺件，不把錯誤頁當內容樣本。

官方來源入口：
- 165 全民防騙網：https://165.npa.gov.tw/
- 警政署公開案例功能說明：https://www.npa.gov.tw/ch/app/data/view%3Fmodule%3Dwg054%26id%3D2206%26serno%3D7218ce42-167b-489b-817b-71fcce2af534
- 數位產業署停止解析清單：https://data.gov.tw/dataset/165027
- 165 遭停止解析涉詐網站：https://data.gov.tw/dataset/176455

## 兩人盲標與複核

填 data/case_collection_template.csv，標註者先不看模型分數，各填標籤與依據。兩人不同就交第三人／老師裁決；缺依據維持 Unresolved。「未被通報」「很多粉絲」「模型說正常」都不是正常標籤依據。個資取得授權、遮蔽姓名／電話，模型與展示版本分開記錄。

首次試辦建議先收 20 筆正常 + 20 筆涉詐候選，檢查證據與原圖是否取得得到。這只是工作量規劃，不是「40 筆就能驗證可靠」。正式數量依獨立帳號數、案例多樣性與統計不確定性決定。

## 切分與執行

同帳號、同網站、同詐騙活動、重複素材放同 group_id，不跨 split。先將獨立 group 分到 calibration／test，test 不用於修門檻或挑模型。再訓練才另建 train；向原權重提供者確認舊訓練資料重疊，確認不了就記為限制。

將已複核 Fraud／Normal 轉填 data/annotation_template.csv，report_path 指向對應報告。各 split 涵蓋相近平台、兩種標籤；頁面不可用案例另報取得率，不能偷偷排除來美化結果。

執行：python evaluate.py --manifest data/my_labeled_cases.csv --output artifacts/evaluation.json

比較網址規則、MacBERT、融合的 Precision、Recall、F1、Unknown coverage、混淆矩陣與誤判案例。校準只在 calibration 擬合，最後在獨立 test 評估。提供每類數量、group 數、來源與標註分歧。歷史涉詐標籤不代表同網址今天的內容相同。

## 分工

- A：收集截圖／文字，保存原件及 OCR 錯誤。
- B：擷取、保存可用性紀錄與 report_path、跑評估。
- C：蒐集涉詐網域來源、核對來源時間及規則。
- 三人輪流盲標，老師協助裁決難例與授權。
